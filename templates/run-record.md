# 实验记录

可用表格、配置文件或现有日志记录以下内容，已有信息直接引用。

- 运行编号 `run_id`：<稳定编号，例如日期加简短名称；结果主张、优化提案等模板用它引用这次运行>
- 规格 `spec_id/version`、父运行 `parent_run_id` 与变更理由：<首轮父运行写 none；普通修复也保留与失败尝试的关系>
- 实验目的与本次改动：<...>
- 代码版本：<commit 或可恢复的实际代码快照>
- 数据/环境和切分：<版本或位置>
- 运行命令、完整配置与必要软件环境：<...>
- 种子、硬件和大致耗时：<实际使用的信息>
- 远端作业、日志、检查点与结果位置：<...>
- 实际状态、主要指标和失败原因：<未执行时注明；运行失败和有效负结果分别说明>
- 有效性检查与证据位置：<执行完成不等于有效；区分未检查/通过/失败>
- 已用/剩余资源、尝试次数与停止条件：<未知保持未知；以调度器或实际记录为准>
- 最近查询时间与恢复动作：<先查现有作业，无法查询保持未知；不要重复提交>
- 简短发现与下一步：<...>

一张表可以记录多个实验。不必为每次运行创建完整报告；主要论文结果应能据此找到实际配置、原始输出和重跑入口。

需要自动核对时，可由工具维护 [JSON 清单](run-manifest.example.json)，无需同时手填两套记录。字段、比较和检查限制见[实验反馈与证据链](../docs/experiment-loop.md)。
