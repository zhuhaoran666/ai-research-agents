# nnU-Net 对框架的研究启发

参考 [Isensee 等的 nnU-Net 论文](https://doi.org/10.1038/s41592-020-01008-z)：在线发表于 2020 年，刊于 Nature Methods 2021 年第 18 卷。正式发表版摘要报告在 23 个公开竞赛数据集上的比较结果。

我们借鉴其方法组织与实证研究方式，按当前课题选择适用部分。日常遵循[轻量研究工作流](workflows.md)，不要求复制医学分割算法、自动配置机制或实验数量。

## 从论文中借鉴什么

| nnU-Net 的做法 | 在通用 AI 研究中如何使用 |
|---|---|
| 将预处理、网络架构、训练和后处理作为相互关联的系统 | 理解方法的完整实现链，检查性能是否依赖被忽略的实现选择 |
| 把设计选择分为固定参数、相互依赖的规则和经验决策 | 说清哪些是方法本身、哪些随任务调整、哪些由实验选择；可以直接写在方法笔记或配置中 |
| 用多个公开任务评价方法 | 对通用方法选择有差异的任务检验效果，报告有效条件和失败情况 |
| 提供可用的软件流程 | 让别人能取得实现、准备数据、运行主要实验并理解结果 |

这些内容同时能构成论文的 Method、Experiments 和 Discussion。研究贡献可以来自已有技术的合理组织、跨领域迁移和可靠工具，具体贡献仍由已有工作对比和实验支持。

## 怎样嵌入我们的协作

1. **你和方法规划 Agent 共同设计。** 先明确问题、核心方法和最值得验证的疑问；文献检索提供方法细节，代码角色补充数据与执行可行性，导师帮助取舍。
2. **AI 实现并先做小试。** 用强基线和少量关键对照判断是否值得继续，再扩展到有代表性的任务。
3. **根据真实结果完善方法。** 结果分析与方法规划联合诊断和提出改进；你参与重要取舍，代码 Agent 接着实现与运行。
4. **边研究边组织文章。** 写作画图 Agent 梳理论证与可视化，指出哪些结论缺少支持；选择补实验或调整表述，最终留下代码、配置、结果与复现说明，交审稿人独立评审。

固定配置研究可以直接记录实际设置；只有研究涉及自动配置或候选选择时，才需要详细的任务画像与配置规则。

## 在影响结论时进一步检查

- 基线是否足够合理，改进是否来自额外数据、预算或其他不受控变化。
- 是否确实观察到机制改善，以及失败任务是否改变了适用范围。
- 用于选型的结果是否又被当作最终性能；独立评价或更严谨的验证设计按具体主张安排。
- 多任务表现是否足以支持所写结论；声称迁移到新任务时，说明规则开发是否接触过这些任务。
- 主要实验和图表能否找到实际代码、配置、输入与输出。

这些问题用于发现论文的重要缺口，可在讨论和笔记中解决。更细的[配置模板](../templates/configuration-policy.md)和[证据矩阵](../templates/claim-evidence-matrix.md)按需要使用。

## 来源与版本

正式论文支持本文关于系统配置、设计决策类型和 23 个公开数据集的概括。[作者预印本](https://ar5iv.labs.arxiv.org/html/1904.08128)提供数据指纹、配置生成和交叉验证选择等方法细节；其数据集数量与正式版不同，不能混用。

[官方现行 v2 概念说明](https://github.com/MIC-DKFZ/nnUNet/blob/master/documentation/explanation/how-nnunet-works.md)和[操作文档](https://github.com/MIC-DKFZ/nnUNet/blob/master/documentation/getting-started/README.md)展示当前的数据准备、规划/预处理、训练、配置选择与推理。v2 命令和实现细节不能直接归为 2021 年论文内容。

上面的人机分工与工作方式是本框架的设计，不是 nnU-Net 原文提出的多智能体流程。
