# 人与 Agent 的日常协作

研究者与导师 Agent 保持一个主要讨论入口，围绕当前问题安排工作。你深度参与方法和实验设计；七个角色按需协作，代码统一实现与运行，方法规划与分析联合优化，写作画图与独立审稿各司其职。

导师按[逐步引导](mentor-guided-intake.md)收集当前所需信息，从当前缺口开始，不从 idea 问卷重来。读取材料、安排调查和维护笔记等每项操作都先说明目的、范围及影响，与用户讨论并明确确认；统一边界见[共享约定](../agents/README.md)“人在回路”。

## 工作怎样推进

- **一起讨论：** 每项操作及新发散的 idea、替代方案和优化建议都先讨论，明确确认后执行。
- **交给后台：** 文献深读、代码实现、远程实验等后台工作，只执行用户明确确认的具体动作与资源范围。
- **重复复用：** 稳定且经常出现的动作，例如整理实验日志、生成图表，可提出沉淀为 Skill 的建议，确认后再创建。

这些方式随任务切换。用户可以一次讨论并确认明确列出的操作清单；已有授权只覆盖该清单及其边界，不因总体目标或资源可用而扩大。派工本身先由用户确认，子代理继承同一操作边界，导师不能代用户批准；[简短任务模板](../templates/task.md)可选用。

## 前台保持讨论，长工作分批完成

前台先用几句话说明当前理解、有用状态和可讨论的下一步，不等完整检索或分析结束才反馈。每轮聚焦一个科研决策，需要比较时给两三个具体选项，说明已有依据、差异与仍未知的条件；只问影响当前选择的少量问题，复用已回答的信息，让研究者把精力放在科研判断上。

长时间阅读、方案比较和计算，在客户端支持且用户已确认具体操作后交给后台。前台保留讨论入口；研究者追问、纠正或插入问题时，尽快简短回应，再把新信息整合进原目标与已确认清单。新的操作或发散想法先带回讨论，后台不自行扩大权限、范围或资源。

长任务按篇、按比较或按运行批次返回：已核实的发现及依据、尚未确认的内容、下一批交付。在实际能力允许时，约每 30–60 秒提供一次有意义的更新；没有变化时不反复刷工具细节或空泛进度。完成一批就交付可用部分，让研究者能据此继续讨论。

只有实际启动成功才称“已在后台运行”。客户端不支持后台、不能及时接收新消息或无法中断当前操作时，如实说明限制，把已确认工作拆成较短批次，在批次之间恢复互动；不承诺做不到的实时响应或随时中断。收到停止或调整要求后，及时处理并核对实际任务状态，再汇报结果。

## 你主要参与什么

你可以随时介入；研究问题、方法机制、任务选择、强基线、关键消融以及结果后的方法取舍都共同推敲。AI 带着具体候选、缺点、可行性判断和成本讨论，关键未知可提出小实验调查建议，确认后再执行。

实验设计不要求一次写全。先查同问题已有解法、局限和基线，再调查可迁移方法，选择最有信息量的下一步实验。前期读别人如何做研究、如何写文章，实验积累后集中分析写作，再边写边完善方案。写作和最终审稿都以实际的广泛文献阅读为基础。

## AI 什么时候主动反馈

在提出方案、基线试跑和出现新结果时，AI 都留意明显缺陷，通常用几句话说明：

- 发现了什么，依据在哪。
- 对方法或结论有什么影响。
- 建议下一步做什么，是否需要你的取舍。

重大方法改变、结果与预期冲突、需要额外资源时及时讨论；普通修复、范围内探索和核验也只执行已明确确认的动作。最终稿经用户确认后安排独立的写作专家和领域专家分别审查语言与学术表达、同行写法与研究证据。领域专家深入阅读和补查文献，导师汇总两个报告。日常局部审校可只选有关专家，无需为每个子任务另开核验报告。

## 记录和后台运行

每个角色按[RSI 约定](rsi.md)理解用户要求、反馈与实际失败，提出修正当前工作、保存经验或改进验证方法的建议；相关操作先讨论确认，不自行启动额外角色或长期后台任务。只汇报真正改变后续做法的内容，未检验的调整如实标为候选。

导师在已确认的范围内维护[本地用户档案](../profiles/README.md)，把明确习惯与候选观察分开；每次分派只带上有关偏好。意图或操作范围不清时，用简短问题与你确认；等待期间只执行其他已讨论确认的动作，没有则等待。沉默不算同意，普通细节也不自动获得授权。

研究笔记保存重要想法、取舍与发现；代码/配置和实验日志保存实际执行。现有工具已经记录的信息直接链接，避免重新填表。

派出子代理或并行实例后，一分钟内检查首个输出里有没有接口错误（例如模型不可用、认证失败）；空结果先查日志，不当作“没有发现”。可用的模型要显式指定，不依赖默认路由。长的精读或检索子任务按篇或按批落盘，中途停止时已完成的部分仍可使用。

建议关注一个实时任务和一两个后台任务，具体派工与后台动作由用户确认。长实验将保存作业 ID、产物位置和恢复查询列入操作清单；断线后只执行已确认的状态检查，不自行重启。计算分配和执行预算沿用项目环境规则。阶段性汇报聚焦发现、问题和下一步，按用户需要再调整频率。

运行与恢复细节见[实验反馈闭环](experiment-loop.md)。执行状态、有效性检查和科学解释分别记录；调度器无法查询时保持未知，不重复提交。有效负结果进入项目证据记录，协作策略的改进进入 RSI，不能相互替代。

语音、文本、Markdown 都可作为 idea 入口。每日复盘和个人 Skill 库是可选习惯。对外发送、投稿、发布和普通研究操作均先讨论并明确确认。

更细的调度与交接字段可查[按需模板](../templates/README.md)，日常不要求全部填写。
