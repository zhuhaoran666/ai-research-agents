# 2026 年 10 月的两次真实使用复盘

这是框架第一次用于真实课题的复盘。两次使用都由 Claude Code 主会话按角色顺序执行，部分子任务派给子代理。下文只保留与框架设计有关的经过，课题细节、服务器信息和私有数据均已去除。这次修订（v0.2）的每一处改动都对应下面的一条教训。

## 课题与经过

- **课题 A：交接一篇医学图像分割论文。** 研究者交给 agent 一份交接文档，要求“审核并完成”。文档冻结了主表与消融表，把几组对照臂列为“排除”。agent 逐项核对后发现：
  - 主表的 nnU-Net 基线是看过验证结果后才选定的单个种子，并且提前停止了训练。同一服务器上还有一行按标准设置跑完的 nnU-Net，结果明显更强。
  - 交接文档列为“排除”的对照臂里，有一个正是研究者自己方法的表示消融。研究者后来说明：当时把它排除，是因为不知道这是自己的方法。
  - 稿件声称两个创新点，消融只验证了其中一个。
  - 通过逐例重算、补齐 2×2 消融，并按“与接触面的距离”把误差分档，研究的动机终于有了直接的定量证据。
- **课题 B：具身智能安全的文献调研。** agent 在研究者确认后检索多个来源，读了数十篇摘要，并派出多个子代理精读全文。研究者中途叫停时，子代理只读到一半，读到的内容没有形成结构化结果，最终被丢弃。

## 教训与对应改动

| # | 发生了什么 | 改了哪里 |
|---|---|---|
| 1 | 交接文档里“排除”“冻结”的决定理由不全；研究者本人也说不清某个对照臂是什么 | `mentor`：新增“接手已有项目”，冻结决定先复核其依据，再请研究者确认是否沿用 |
| 2 | 同一个方法在不同文件里有多个内部代号，研究者分不清“哪个才是我们的方法” | `mentor`、`writing`：先建立一张名称表，对研究者和正文只用一套名称；稿件里只写“Ours”和基线的通用名 |
| 3 | 主表基线的设置比标准做法弱，结论被放大 | `method`、`analysis`：新增“基线强度检查”，基线要和同等条件下的标准设置或最强可得版本对照 |
| 4 | 声称两个创新点，只有一个有消融 | `method`、`reviewer`：每个声称的贡献都要有一个只改这一个因素的对照；缺失时写进局限，或收窄贡献 |
| 5 | 整体平均值把局部改进摊薄了；按误差位置分档后，动机才有了证据 | `analysis`：新增“把改进定位到机制作用的位置” |
| 6 | 打平或增益很小的结果容易被说成“有提升” | `analysis`：效应量与体素间距、标注误差等物理尺度对照；配对检验配多重比较校正；没检测到差异不写成“没有变化” |
| 7 | 只做过 64 MB 写入测试就断定“磁盘有空间”；实际配额只剩约 160 MB，导出失败 | `code`：新增“资源与环境的真实检查”，按真实写入量测试，并说明测试本身的局限 |
| 8 | 删除脚本是按猜测的目录名写的，差点删掉方法依赖的 checkpoint | `code`：删除前先列清单（路径、大小、依赖关系），研究者逐项确认，删除后核对受保护文件的哈希 |
| 9 | 子代理被默认路由到一个当前账号不可用的模型，所有结果都是空的；另一次被账号级的 401 错误打断 | `operating-model`：派出子代理后一分钟内检查首个输出里有没有接口错误；可用模型要显式指定 |
| 10 | 两个训练任务在第 0 个 epoch 前卡住近半小时，原因是环境变量与已验证的参考运行不一致 | `code`：首次运行时监控到第一个可观测的进度点；与参考运行保持相同的环境 |
| 11 | 一个子代理把“比较两种方法”的数字记错了，另一个把检索摘要当成原文 | `literature`、`analysis`：子代理的数字和引用在写进结论前，由主会话按原始文件或原文抽查 |
| 12 | 研究者中途叫停，正在读的全文没有留下可用的部分结果 | `literature`、`operating-model`：精读子任务按篇落盘，每读完一篇就写入阅读索引 |
| 13 | 被引用的数据集带有许可限制（衍生标签不允许直接用来训练其他框架），文档里没有任何人提到 | `literature`、`writing`：数据集要核对标签来源和许可条款；标签由模型生成时，要在稿件中说明 |
| 14 | 研究者用“目标”指令一次性交代长任务（例如“改 motivation、补实验、重写文章”），中途又追加新目标 | `mentor`：长目标拆成可检查的里程碑，每完成一项汇报一次；新目标插入时说明它与正在跑的工作是什么关系 |

## 仍未解决

- 这些规则同样只是指令。agent 在两次课题中都违反过其中几条，事后才发现。是否需要用工具约束（例如审稿角色只给只读工具），留待下一轮试用。
- 两次课题的产物都含私有数据，没有收进 `examples/`。真实运行示例仍然缺少。
