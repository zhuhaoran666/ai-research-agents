# 从实验结果到下一步行动

本约定把已有的 ExperimentSpec、实验记录、ResultClaim 和论文来源连起来。项目可以继续使用自己的日志、调度器和目录，不必启用 JSON 清单或新增编排服务。设计来源及适用边界见 [The AI Scientist 学习记录](ai-scientist-lessons.md)。

轻量项目只需在现有笔记中给当前实验约定一个稳定编号与版本，写清比较、评价和资源边界；下文的 `spec_id/version` 也可指向这段笔记。无需因此填写完整 ExperimentSpec。选择机器检查时，才将相关记录映射到 JSON 清单与文件引用。

## 导师先帮助补齐当前输入

导师按[逐步引导](mentor-guided-intake.md)复用已有材料，只补问会改变下一步的信息。研究者不必先知道所有基线、统计方法或运行环境；相关角色先提出具体调查清单，用户确认后调查并给出有依据的候选。按[共享约定](../agents/README.md)，下文的读取、准备、启动、查询、恢复、评价、收集和停止等每项操作都先讨论并明确确认，也可一次确认明确列出的清单。启动实验还需明确比较、数据范围、评价口径、资源和停止条件；已有确认只覆盖其中具体动作，不自动授权新的运行。

## 项目实验适配接口

代码角色在用户确认后，把下面的动作接到项目现有命令或 API。可以是一页说明加几条命令，不要求实现统一类或安装新框架。首次接入提出很小的实际负载及验证步骤，确认后执行；验证通过后若建议扩大，先讨论新的动作与成本。

| 动作 | 必须说清的输入与输出 |
|---|---|
| 准备 | 接收 `spec_id/version`、代码快照、配置、数据与切分版本；核对评价协议和资源范围，返回可执行入口及阻断项 |
| 启动 | 为一次尝试分配新的 `run_id`，保存命令与环境，返回可查询的作业 ID；启动成功不等于实验完成 |
| 查询/恢复 | 用现有作业 ID 查询排队、运行、失败或完成；核对日志和产物后决定等待、续跑或新建尝试，查询失败保持未知，不重复提交 |
| 评价 | 从原始预测、轨迹或日志按固定协议计算指标；返回带定义、单位、方向和聚合方式的结构化结果，以及有效性检查结果 |
| 收集 | 保存代码、配置、切分说明、原始输出、指标、分析与图表的路径及哈希；失败和有效负结果同样保留 |
| 停止 | 支持取消作业；返回实际停止状态、剩余资源和已保存产物。停止请求发出后仍需查询确认 |

评价协议由方法与分析角色维护，基线和方法调用同一版本的评价入口。需要改变指标、切分、纳入规则或后处理时，新建协议版本并说明原因；旧协议下的数字不能直接与新协议比较。实验代码不应自行改写冻结的评价入口；具体的只读挂载、权限隔离和预算限制需要由项目执行环境落实。

## 结果如何分流

先由代码核对执行事实，再由分析和方法判断结果能回答什么；不要把所有不理想的输出都送回调参。

| 观察到的状态 | 下一步与负责人 | 保留什么 |
|---|---|---|
| 有效支持结果：完成检查，且证据在当前范围内支持预期 | `analysis` 复算并检查比较、波动与边界，形成或更新 ResultClaim；`writing` 接入真实表图，正式稿交独立审稿 | 支持与冲突运行、证据范围、计算入口和稿件位置；通过运行检查不自动证明机制 |
| 工程失败：崩溃、超时、缺文件、评价未完成或检查失败 | `code` 提出定位、修复及续跑的具体操作，确认后执行。不能作为假设不成立的证据 | 原作业 ID、错误日志、失败原因、修复差异与尝试关系 |
| 有效负结果：运行和评价有效，但没有支持预期 | `analysis + method` 检查波动、作用范围和替代解释；保留结果，可以补区分性分析、收窄结论，或建议停止 | 全部预定运行、反证、适用条件及尚不能排除的解释 |
| 证据不足：单次波动、关键消融缺失或设置不可比 | 优先用已有产物补查；需新实验时提出能区分解释的最小比较，不把不确定性写成成功或失败 | 影响哪条主张、缺口、候选实验及成本 |
| 方向或关键协议需要变化 | 导师带着证据、选项和成本与研究者讨论；普通修复和局部探索同样只执行已明确确认的动作 | 决定及理由、新 ExperimentSpec 版本与原版本的关联 |

新尝试记录 `parent_run_id`、变更理由、对应规格版本、已用/剩余预算和停止条件。父运行可以是失败或负结果；关系用于追踪决策，不代表子运行一定更好。新的局部探索、解释或优化方案先作为候选与用户讨论，确认前不自行检索验证、实现或运行。不要把“结果不显著”当成自动扩大搜索的理由，也不要为继续运行而改写原成功标准。

## 恢复时先对账

建议的恢复顺序是：读现有记录 → 查询已有作业 → 检查产物完整性和版本 → 更新状态与实际资源 → 讨论续跑或新建运行。只执行用户已确认的查询与检查清单；续跑、新提交或清单外调查需先确认。作业状态、结果文件和日志不一致时保留冲突；无法访问调度器时报告未知，不把未知改成失败，也不重复提交。

未完成的文件不能凭存在性当作完成；原子写入或明确完成标记由项目适配器提供。续跑只能使用与当前代码、配置、数据版本兼容的检查点；改变协议的尝试使用新编号，保留原结果。完成的主要结果应能恢复到当时的实际代码，只有含本地未提交改动的 commit ID 不足以做到这一点。

## 可选的机器检查

需要自动核对时，参考 [JSON 清单](../templates/run-manifest.example.json)，使用 Python 3.9+ 的标准库工具，无需安装依赖：

```sh
python3 scripts/check_evidence.py examples/evidence-demo/manifest.json
python3 -m unittest discover -s tests
```

[合成演示](../examples/evidence-demo/README.md)包含原始预测、评价脚本、指标与报告，只演示追溯方式，不是研究结果。实际项目复制模板后，由代码角色或项目工具填入真实信息，不能原样复用示例数字或哈希。

```sh
python3 scripts/check_evidence.py /path/to/project/manifest.json
python3 scripts/check_evidence.py /path/to/project/manifest.json --compare /path/to/baseline/manifest.json
```

清单的产物路径默认相对各自清单所在目录；使用 `--root /path/to/project` 时，双方路径都相对该项目根。路径与符号链接解析后必须位于根内。检查器只读取清单和相关文件，不启动实验、访问网络或修改产物；失败返回非零状态。

| 字段 | 用途 |
|---|---|
| `run_id / spec / parent_run_id / reason` | 连接规格版本、当前尝试与变更依据 |
| `status / validity` | 区分执行状态与项目声明的有效性检查；有论文数字声明时要求完成且检查通过 |
| `provenance / evaluation` | 标识实际代码、配置、数据、切分、环境、评价版本、选型用途和聚合口径 |
| `job / budget` | 保存查询入口、已用/剩余资源和尝试次数；这是记录，不是资源限制器 |
| `artifacts` | 稳定 ID、根内相对路径及 SHA-256；引用通过 ID 连接 |
| `metrics` | 指标值、定义、单位、方向，以及来源 JSON 的 artifact ID 和 RFC 6901 pointer |
| `claims` | ResultClaim ID、文字、指标、报告数值、舍入容差，以及稿件产物与具体位置 |

检查链为：规格文件 → 运行/评价产物 → 指标来源值 → 声明的报告值与位置。工具核对结构、文件存在与哈希、有限数值、来源 JSON 中的值和声明值；比较模式还核对数据、切分、评价版本及同名指标定义等标识。舍入容差应与报告精度一致，不能为掩盖差异而放宽。

**通过只说明上述记录一致。** 哈希是相对于清单的完整性校验；同时改写文件和哈希无法被它识别。有效性状态仍是项目提供的声明。它不会证明代码实现了假设、评价没有泄漏、自然语言论断或图中每个数字正确，也不会从任意预测格式自动重算指标、判断统计充分性或基线公平性。原始产物的复算由领域评价脚本完成，分析与独立审稿仍需核对科学含义；正式主张不能由工具的通过状态自动升级。

## 在环境中执行资源边界

需要真实限制时，由现有调度器、容器或受限账户在实验进程之外设置时限、并发、存储、网络和凭证范围，并保存执行记录。模型不应有权限通过修改自己的脚本提高额度或绕开评价隔离。本仓库提供适配约定与只读检查器，未实现这些执行控制；手填 `budget` 或提示词都不能替代实际限制。

先选一个熟悉的小课题试用：检查能否恢复中断作业、保留负结果、发现一次人为置入的数值或协议不一致，并记录研究者纠正所需时间。试点指标和来源边界见[学习记录](ai-scientist-lessons.md)，不以生成论文数量或自评得分代替有效性。
