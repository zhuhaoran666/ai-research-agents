# 按论文逻辑组织的研究工作流

默认分为四个工作板块，可以并行、跳转和重复。已有论文、代码或结果时从当前问题直接进入；新的发现随时改变研究计划。阶段完成以产生有用材料为准，后续工作直接接着推进。

由[七个 Agent](../agents/README.md)协作，导师贯穿各板块，关注方向、质量、用户意图和习惯。各角色优先检索、核读和复用他人工作；日常直接交换有用材料，最终保留独立实质审稿。

## 1. 问题与文献：要解决什么，已有方法为何不足

**主要协作：你、导师、文献检索和方法规划 Agent。**

初步想法可以先用[idea 描述指南](idea-guideline.md)讲清楚。口述、零散要点或暂无方法都可以，导师区分观察依据、原因猜测与初步解法，只补问影响下一步的内容，并将共识接入研究笔记。

调研优先从目标任务的已有方法与问题现状出发，再评价用户提出的解决方案。方法关键词可以保留为后续线索，避免一开始只搜支持初步方案的文章，或把它能优化某个目标当作采用它的充分理由。

1. 从实际问题和初步解决方法出发，说明任务、预期价值、已有直觉和未知项。
2. 每轮调研必查 [PaperNotes](https://papernotes.org/)、[Google Scholar](https://scholar.google.com/)、[arXiv](https://arxiv.org/)，并按[领域来源清单](literature-sources.md)补查：医学图像必须查 MICCAI、ISBI 及 MIA、TMI、TPAMI；具身智能重点查 IROS、ICRA，并按任务补 RSS、CoRL。先判断这个问题是否已被解决、在什么条件下解决、仍有哪些局限。记录各来源的实际检索情况，按[文献角色要求](../agents/literature.md)处理访问限制、论文版本与已有记录复用；读已有方案原文与实现，形成合理 baseline。
3. 再查其他领域或相邻任务的方法，看哪些机制可能在当前问题上起作用，需要什么适配；也找反例与简单替代方案。
4. 建立覆盖问题现状、基线、迁移来源和反证的文献视野，精读影响判断的原文，保存实际阅读范围与来源。写作与审稿 Agent 也要实际读文献，不能只接收摘要。
5. 同时看参考论文怎样组织问题、方法、实验和图表，积累可借鉴的写法；用自己的材料建立论证。
6. 在研究笔记中写下值得先试的方案。必要时边查文献边试代码，见[文献与写作协作](literature-and-writing.md)。

**留下什么：** 问题描述、共享阅读索引、基线与方法比较、写法参考和初步想法。可先积累 Introduction / Related Work 的段落笔记，集中写作随实验认识展开。尚未核实的内容注明即可。

## 2. 方法与实验设计：怎么做，如何知道它是否有效

**主要协作：你、方法规划 Agent；代码与结果分析提供可行性和验证设计反馈，导师帮助取舍。**

1. 和你共同拆解方法，说明核心机制、模块关系以及实现上最可能遇到的困难。
2. AI 主动检查数据是否够用、基线是否合理、方法是否可实现、显存和时间是否可承受，并指出最影响结论的设计缺口。
3. 一起确定值得先跑的实验：任务或数据、基线、主要指标、关键对照、预计成本。优先选择能回答当前疑问的最小实验。
4. 有初步证据后再扩展任务、消融和边界分析。通用方法或工具优先覆盖有实质差异的任务；实验规模随主张和资源调整。

**留下什么：** 方法草图和简短实验表。这些内容将来构成 Method / Experimental Setup。无需逐实验填写完整协议模板；重要取舍在笔记里记下理由。

| 想回答的问题 | 怎么比较 | 看什么结果 | 大致成本/当前进展 |
|---|---|---|---|
| <当前最关键的疑问> | <任务、基线或改动> | <指标或观察> | <估算或实际进展> |

## 3. 实现、运行和分析：把想法跑出来，再根据结果改进

**主要协作：代码 Agent 统一实现和运行，结果分析与方法规划联合诊断和优化；你参与解释及重要取舍。**

1. 接入数据和基线，实现当前方法，做足以发现明显错误的小检查。
2. 在已商定资源范围内运行实验，保存实际代码、配置、命令、日志和结果位置；失败运行也留记录。
3. 结果分析从原始指标或预测计算表格和诊断结果，比较效果、波动、成本和失败案例；写作画图角色据此生成论文图表，保留相同数据与生成入口。
4. AI 说明“观察到了什么、可能为什么、最值得再试什么”。普通修复、局部调参与约定范围内探索直接继续；重大方法变化或新增投入与你讨论。
5. 新的优化先跑能区分解释的比较，再决定是否扩大。结果不支持原想法时，修改方法、收窄结论或停止都可以。

**留下什么：** 可运行实现、实验记录、结果表图和关键发现，逐步形成 Results / Analysis。

基本科学检查随工作完成：比较使用合理的数据与评价口径，最终测试不被反复用于择优，未实际观察的提升不能写成结果。对新任务泛化作结论时，说明方法开发是否接触过这些任务；更严格的留出或外层评价由具体主张决定。

遇到可疑数字或复现偏差，代码与分析先查原始材料；重要科学争议可请审稿人独立检查，导师汇总分歧。无需每次正常交接都安排独立验收。

## 4. 文献驱动的写作与最终审稿

**主要协作：你、写作画图 Agent；方法规划与结果分析协作，最终由独立审稿人集中评审，导师协调修订。**

1. 当实验积累能形成初步认识时，你与分析和写作 Agent 集中梳理结果，形成文章主线。没有固定实验数量要求。
2. 写作画图 Agent 在已有广泛阅读基础上补查缺口，精读核心方法与论证来源，参考相近研究的文字与图形组织；正文和图表建立在自己的真实方法与结果上。
3. 边写作边完善方案：区分解释不足、已有数据尚未分析、需要补实验或改方法，与你和相关 Agent 一起处理。发现问题不意味着每次都重做实验。
4. 用实际结果更新贡献与局限，保留有影响的失败与适用边界；跨领域迁移、适配、整合和可用工具都可以形成贡献，无需包装成彻底原创。
5. 最终安排 [专业审稿人](../agents/manuscript-reviewer.md) 独立评审。它实际读文献，并从问题本身补查作者引用之外的方案，优先判断问题价值、贡献定位、强基线、方法合理性、归因与结论范围；措辞和格式在实质问题之后处理。
6. 审稿人给出有稿件定位和原文依据的问题，以及补写、补分析或最小补实验建议。导师汇总优先级和处理方式，写作画图、分析、方法规划或代码角色处理对应问题；重大取舍与你讨论，复审集中检查已有问题和新改动。
7. 整理主要实验的运行入口、代码配置、数据与表图来源，核对关键引用与数字。缺少关键原文或实验证据时明确最终判断的限制；实际发布或投稿单独执行。

**留下什么：** 稿件、参考文献、图表、简短实质审稿报告和能使用的复现说明。阅读覆盖及判断限制在报告中简要披露；复现深度依据交付需要安排，如实说明已重跑的步骤。

## 日常材料与交接

新课题可用[研究笔记模板](../templates/research-note.md)开始，配合现有代码仓库和实验日志。其他 Agent 通过文件位置、当前发现与下一步说明接手，重复信息直接引用。

导师按需读取[本地用户档案](../profiles/README.md)安排协作；遇到明确偏好纠正就更新，反复观察保留候选及来源。项目特例留在当前笔记，习惯不能改变证据或扩大资源边界。

```text
research.md       问题、文献、方法、实验计划、关键发现
src/ + configs/   实现和实际配置
runs/             命令、日志、指标及产物位置
paper/            随研究积累的稿件、图表和引用
```

目录只是示例，可以沿用已有仓库结构。

复杂课题确实需要更详细的分工、配置规则或独立复现时，再选用[扩展模板](../templates/README.md)。默认不要求逐任务审批、完整状态机、成套交接文档或固定复现等级。
