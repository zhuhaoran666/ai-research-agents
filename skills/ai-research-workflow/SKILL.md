# 科研代理协作入口

从用户当前困难与已有材料出发，选择能交付实际结果的最少角色。阶段可以并行、返回或省略，角色不必常驻；协调的价值在于解除研究瓶颈与连接证据。

## 进入当前任务

复用会话、项目规则、笔记、代码、运行与稿件，以及已有答案、决定和授权。先辨认本次要交付什么、已有依据是什么、下一步被什么阻碍；轻量任务可以留在对话中，持久记录沿用项目现有位置。

只有无法自行核实且会改变下一步的重要未知项才需要澄清；等待回答时继续不依赖该决定的工作。研究问题、核心假设、关键协议和主张的重大取舍需要研究者参与，已授权范围内的调查、制作与验证直接推进。角色或工具可用不扩大资源、数据外送或发布权限。

## 按职责加载技能

只加载当前任务需要的技能与参考；表中的名称是职责和技能绑定，不要求客户端使用相同的角色名。

| 职责 / Codex 角色 | 主技能 | 本次应交付什么 |
|---|---|---|
| 导师 `research-mentor` | [research-mentor](../research-mentor/SKILL.md) | 有依据的优先级、可执行派工与连续交接 |
| 文献 `research-literature` | [research-literature](../research-literature/SKILL.md) | 最接近工作、强基线、反证及真实核读范围 |
| 方法 `research-method` | [research-method](../research-method/SKILL.md) | 机制假设、区分性验证、公平协议与取舍 |
| 实现 `research-code` | [research-code](../research-code/SKILL.md) | 真实实现、运行状态、恢复依据与复现产物 |
| 分析 `research-analysis` | [research-analysis](../research-analysis/SKILL.md) | 原始复算、可比性、失败诊断与主张范围 |
| 写作 `research-writing` | [research-paper-writing](../research-paper-writing/SKILL.md) | 基于作者材料的论证、正文与图表叙事 |
| 审稿协调 `research-reviewer` | [research-reviewer](../research-reviewer/SKILL.md) | 两份原报告、问题路由、优先级和保留的分歧 |
| 写作审稿 `research-review-writing` | [research-review-writing](../research-review-writing/SKILL.md) | 有定位的语言问题与保持科学含义的最小改法 |
| 领域审稿 `research-review-domain` | [research-review-domain](../research-review-domain/SKILL.md) | 原文与实际证据支持的研究缺陷或论证改进 |
| 冗余审校 `research-review-redundancy` | [research-review-redundancy](../research-review-redundancy/SKILL.md) | 按请求检测可删冗余，或交付保持原意的精简稿 |

实现任务按需组合 [readable-code-engineer](../readable-code-engineer/SKILL.md)，保持入口、主流程和修改位置清楚。它处理工程可维护性，`research-code` 处理科学实现与实验，不重复建立两套运行环境。

需要完整综述时用 `deep-research` 等对应流程；单段引言、局部润色、图表或文件制作选用已有专长。成像研究按需复用 `radiology-*`，其他领域使用相应一手来源与工具；不因技能可用就批量加载。

本入口组合相邻的角色技能。跨工具移植时携带所用角色的完整技能目录；缺少角色配置时可向通用代理明确职责和实际技能路径，不把文件存在当作已自动加载。

## 派工与共享产物

- 任务交代问题、输入位置与版本、负责人、交付及有关资源边界即可；代码修改额外明确可写文件或模块、他人并行工作及保留现有改动。
- 独立任务可并行，依赖前一产物的工作顺序推进；同一文件指定一位整合者。工具不支持子代理时直接或顺序完成，并披露相应独立性限制。
- 启动后核对实际状态与产物。模型和推理设置默认继承当前选择；只有明确要求且工具支持时覆盖，不能把接口报错当任务已启动。
- 交接传递原始产物与判断依据，区分观察、解释和计划。资料转发、子代理自报数字与团队共识不等于独立核实。
- 用户插入问题或纠正时先回应，结合新信息继续原目标；任务只在明确取消、替换或冲突时改变，不因一条追问清空已有工作。

## 连接运行与主张

主要结果能回到实际代码、配置、数据与划分、评价口径、运行及原始输出。记录按项目规模选择，沿用现有格式；示例、模板和合成试跑不作为真实研究结果。

执行状态与科学判断分别记录：未执行、仍运行、未知、工程失败或已完成，不自动对应有效支持、有效负结果或证据不足。旧作业状态未知先查询与核对产物，不重复提交；运行成功和检查器通过都不能单独证明研究有效。

计划或协议变化保留版本与理由，失败、负结果和旧协议结果不覆盖。新比较应回答具体疑问并处于已有授权范围；证据不足时同时考虑补证与收窄主张，不以扩大搜索维持早期故事。

## 独立审稿与修订

最终审稿经 `research-reviewer` 将同一冻结版本及原始证据交给两个新上下文专家；首轮不附作者自评、辩护或另一专家结论。语言问题用 `Wn`，领域问题用 `Dn`，保留原报告与分歧，协调者不充当第三位实质审稿人。

复审沿用问题编号，以真实修订位置或补证关闭；出现反证可沿原编号重开。没有独立上下文或一位专家未完成时说明实际范围，不能把作者自查或角色切换冒充双专家独立审稿。局部审校只调用对应专家，冗余审校按需使用。

## 交付与经验

交付本次请求的成果、实际验证、影响判断的缺口和下一步责任。无需为轻量任务建立成套表格、固定阶段门禁或永久进程。

根据真实失败、用户明确反馈和可检查的改动修正策略；未验证的做法保持候选，策略改善与科学方法有效性分开。私人档案、研究数据和角色经验留在原有私人范围，不复制进公开技能或分享包。
