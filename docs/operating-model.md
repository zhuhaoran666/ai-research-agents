# 人与 Agent 的日常协作

研究者与导师 Agent 保持一个主要讨论入口，围绕当前问题安排工作。你深度参与方法和实验设计；七个角色按需协作，代码统一实现与运行，方法规划与分析联合优化，写作画图与独立审稿各司其职。

## 工作怎样推进

- **一起讨论：** idea、难懂的方法、关键实验和结果解释，需要反馈时就交流。
- **交给后台：** 文献深读、代码实现、远程实验等目标清楚的工作，在现有资源范围内持续推进。
- **重复复用：** 稳定且经常出现的动作，例如整理实验日志、生成图表，可以逐渐沉淀成 Skill。

这些方式随任务切换。已有目标和授权持续有效，正常工作不用逐项重问。导师分派时说清任务、资料、交付和必要资源边界即可；[简短任务模板](../templates/task.md)可选用。

## 你主要参与什么

你可以随时介入；最值得共同推敲的是研究问题、方法机制、任务选择、强基线、关键消融以及结果后的方法取舍。AI 带着具体候选、缺点、可行性判断和成本讨论，关键未知可以先用小实验调查。

实验设计不要求一次写全。先查同问题已有解法、局限和基线，再调查可迁移方法，选择最有信息量的下一步实验。前期读别人如何做研究、如何写文章，实验积累后集中分析写作，再边写边完善方案。写作和最终审稿都以实际的广泛文献阅读为基础。

## AI 什么时候主动反馈

在提出方案、基线试跑和出现新结果时，AI 都留意明显缺陷，通常用几句话说明：

- 发现了什么，依据在哪。
- 对方法或结论有什么影响。
- 建议下一步做什么，是否需要你的取舍。

重大方法改变、结果与预期冲突、需要额外资源时及时讨论；普通修复和范围内探索继续执行。日常核验按疑点调用，最终稿安排独立的专业审稿人深入阅读和补查文献，集中提出影响贡献与结论的问题。日常无需为每个子任务另开核验报告。

## 记录和后台运行

导师维护[本地用户档案](../profiles/README.md)，把明确习惯与候选观察分开；每次分派只带上有关偏好。重要意图不清且影响方向、主要比较、预算或写作目标时先查上下文，再用简短问题与你确认；与此同时继续不依赖答案的工作。普通细节自主处理，阶段性总结只报告真正有用的变化。

研究笔记保存重要想法、取舍与发现；代码/配置和实验日志保存实际执行。现有工具已经记录的信息直接链接，避免重新填表。

默认关注一个实时任务和一两个后台任务，可随工作量调整。长实验保存作业 ID 和产物位置，断线先查状态；计算分配和执行预算沿用项目环境规则。阶段性汇报聚焦发现、问题和下一步，按用户需要再调整频率。

语音、文本、Markdown 都可作为 idea 入口。每日复盘和个人 Skill 库是可选习惯。对外发送、投稿或发布沿用明确授权，普通研究协作正常推进。

更细的调度与交接字段可查[按需模板](../templates/README.md)，日常不要求全部填写。
