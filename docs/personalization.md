# 用户习惯与框架适配

相关偏好集中保存在本地 `profiles/user.md`，可从[档案模板](../profiles/README.md)创建，由[导师 Agent](../agents/mentor.md)维护。没有档案时根据当前任务推进，按需补充；这里定义怎样使用和更新记录，避免多份偏好互相矛盾。

## 四类信息分开保存

| 信息 | 保存位置 | 用途 |
|---|---|---|
| 用户明确的背景与长期偏好 | `profiles/user.md` | 跨项目协作、工具习惯、研究和写作偏好 |
| 当前项目的决定与临时要求 | 项目研究笔记 | 本课题的数据、方法、预算、目标和暂时例外 |
| 重复行为推测出的习惯 | 用户档案的候选区 | 有来源的待验证推断，不冒充用户指令 |
| 已验证的研究操作经验 | 项目笔记或可选 Skill | 带适用条件的操作经验，不等于用户偏好 |

## 总结、应用与纠正

1. 导师在新任务开始时读取相关偏好，结合本次意图安排工作；不把全部历史都塞给每个角色。
2. 用户明确提出或纠正偏好时，直接更新相关记录并应用，写明来源与适用范围；无需再次询问同一件事。
3. 只有观察时，记录具体反馈或反复出现的选择、次数和适用范围，作为候选。不能从一次拒绝、沉默或某个项目的表现推断用户性格、预算或长期研究口味。
4. 推断会显著改变研究方向、主要比较、资源或写作目标时，导师提出简短具体问题；确认前按既有明确要求做事，并继续不依赖答案的工作。
5. 阶段性总结只汇报真正改变协作的新增认识。用户可修改或移除，后续不从旧记录自动恢复；不为每次交流生成一份冗长“用户画像”。
6. 用户最新明确要求优先，单项目例外保留项目范围；新证据也可以推翻旧经验。偏好不能改变实验事实、审稿意见或扩大工具与资源授权。

模板不预设使用者的研究领域、工具、语言或长期习惯。共同设计、文献驱动和独立审稿是框架的默认工作方式；具体参与程度、表达和执行工具可随项目调整。

## 七角色怎样适配同一个用户

| 角色 | 应用方式 |
|---|---|
| 文献检索 | 从用户常用来源出发，优先解释方法与实现条件，主动跨领域补查 |
| 方法规划 | 提供能与用户共同取舍的实验，而非一次交一套无法讨论的方案 |
| 代码 | 复用项目仓库与配置好的本地或远程环境，把数据、baseline、方法和消融跑起来 |
| 结果分析 | 聚焦真实不足、成本和下一步，和方法规划联合优化 |
| 写作画图 | 参考同类好文章的论证和图形组织，用实际结果呈现贡献 |
| 审稿人 | 实际广泛读文献，优先提出影响研究的真正问题，保持独立 |
| 导师 | 按习惯安排优先级、解释取舍、澄清重要歧义并修正自身判断 |

## 可移植与领域差异

迁移框架时携带角色指令，并在受控环境中加载相关用户档案和项目笔记。公共模板与私人内容分开同步。目标工具需实际加载这些文件；单独保存文件不代表所有未来会话或外部应用已经自动读取。无需绑定某家模型服务或数据库。

具体任务再补领域条件：医学图像的患者/中心与预处理，具身任务的环境、动作与场景，语言模型的 checkpoint/数据与推理设置，强化学习的奖励、交互预算与评价随机性。这些条件进入项目记录，不自动变成所有研究的固定规则。

服务器和数据位置、预算、工具权限及论文目标按项目需要提供。共享档案只保存相关偏好，不保存凭证和服务器密钥。
