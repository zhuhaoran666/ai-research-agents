# 怎样向研究 Agent 描述一个 idea

这份指南帮助你把初步想法说清楚，让 Agent 能检索相关工作、指出不足，并与你共同设计验证实验。可以直接口述或写几个要点，已有论文、代码或实验也能作为起点。没有确定方法、还没跑实验，或暂时不知道原因，都可以开始。

先描述真实问题和你的直觉。论文的贡献与结论随文献和实验逐步形成，不需要在开始时写完整故事。

## 先回答四个问题

### 1. 你在什么任务中遇到了什么问题？

说明输入、期望输出，以及困难出现的具体条件。最好给一个失败例子，解释它为什么值得解决：影响任务质量、可靠性、效率、成本，还是实际使用？

例如，“想做更好的模型”还很宽泛；“希望在有限训练预算下适配预训练模型，目前不知道不同任务是否需要更新相同模块”已经能引导检索和实验。失败例子可以是定性观察，不必先有完整统计。

### 2. 你已经看到了什么，依据是什么？

写清楚哪些是自己的实验观察，哪些来自论文，哪些只是直觉。有材料就链接失败案例、图表、日志或论文位置；还没有材料就注明待验证。

“某个 baseline 在这些条件下失败”与“现有方法都无法解决”是不同范围的判断。后者需要文献和比较支持。检索尚未找到解法，也不能直接推断没有人做过。

### 3. 你怎样解释这个问题，想尝试什么？

把两件事分开说：

- **原因猜测：** 你认为哪些因素可能导致现象？还有没有其他解释？原因尚不明确也可以。
- **初步方法：** 你准备改动什么，预计通过什么机制改善问题？可以用一句话、流程草图或伪代码说明；没有方法就写“暂无方法”。

方法可以来自已有论文、其他领域或自己的经验。若是借鉴，说明来源和直觉：原方法利用了什么性质，当前任务是否可能具有相同性质，需要调整哪里。暂时不清楚的部分交给检索和讨论，不能仅凭两个任务的表面相似认定迁移有效。

### 4. 你现在有什么，希望这次先做什么？

简要列出已有论文、数据、代码、结果和大致资源。资源未定就注明未定，知道时再补充计算环境、可承担的运行时间与预算。

说明本次最想推进的工作，例如：查问题是否已被解决、理解某个方法、比较候选方案、共同设计一个小实验、分析失败结果，或组织已有材料开始写作。也可以指出你最想参与的设计选择，如核心假设、数据集、基线或关键对照。

## 可直接复制的起始描述

> 我在研究【任务与输入/输出】，关注【具体条件下的问题及其价值】。目前观察到【现象或失败例子】，依据是【实验记录／论文／个人观察／尚待验证的直觉】。我猜测原因可能是【解释／尚不明确】，想尝试【初步方法／暂无方法】，因为【预计起作用的机制／尚待讨论】。我已有【论文、数据、代码、结果和大致资源】，希望这次先一起【下一步目标】，其中【重要设计选择】希望由我参与讨论。

需要分项填写时使用[idea 模板](../templates/idea.md)。两种方式任选一种，后续内容接入[研究笔记](../templates/research-note.md)，无需重复维护多份相同材料。

## 讨论到实验时，再按需补充

这些内容随研究逐步明确，不要求一开始全部填齐：

- **最接近的已有解法：** 已读过哪些论文？它们能做到什么，你关心的不足在哪个条件下出现？引用先给可核对的标题或链接，阅读不足就注明。
- **第一个验证问题：** 哪个比较最能判断这个想法是否值得继续？与谁比、改变什么、看什么结果？哪些观察会削弱假设，哪些只能说明性能变化、还不能解释原因？
- **主要可行性疑问：** 数据是否可用，方法能否实现，计算成本是否可承受？哪些信息还需要代码或文献角色核查？
- **预期价值与适用范围：** 更好的质量、效率、可靠性，方法适配、通用工具或实证认识都可以。跨任务主张需要说明可能共享的性质、任务差异和预期失效条件；任务数量随问题和资源决定。

初步没有提升时也可以讨论。它可能说明实现有问题、解释不成立、基线已足够强，或方法只适用于某些条件。下一步由证据决定。

## 一个完整起点的例子

**以下是虚构设想，只演示描述方式；没有真实检索、运行或结果。**

> 我想研究有限计算预算下的预训练模型适配：输入是预训练模型与新任务的训练数据，输出是适配后的模型。我关心在相同总预算下，能否取得更好的任务质量。目前只是怀疑不同任务需要更新的模块不同，还没有实验支持。我想用一次短暂探测选择更新模块，原因假设是模块对当前任务的贡献可能不均匀；这个信号是否可靠、探测开销是否值得，都不确定。我还没查清选择性更新的已有方案，没有确定数据集，已有可微调的代码，运行预算也需要估算。这次希望先查最接近的方法，再一起设计一个能判断选择策略是否有价值的小实验；基线和预算口径由我参与确定。

这段描述留下了几个明确问题：已有方案是否覆盖设想，探测信号是否可靠，收益能否抵消全部额外开销。Agent 可以先调查这些问题，再讨论方法增量和跨任务验证。

## Agent 收到后应该怎样回应

导师先利用已有上下文，通常给出以下简短反馈：

1. 用自己的话复述研究问题、初步解释与方法，分别注明用户报告的观察、已有依据和待验证判断。
2. 复用用户已给的信息，信息足够时直接推进；需要澄清时，优先问一至三个会改变当前研究选择的关键问题。其余未知保持可见，继续开展不依赖答案的工作。
3. 安排文献角色查问题现状、最接近的方案、强基线和反证；对来源不充分的全称判断保持待核实。
4. 方法角色与你讨论少量候选方案和最值得做的验证，主动指出替代解释、实现困难与成本未知；比较条件、指标和重要取舍由双方共同明确。
5. 把共识、待查项和下一步记入已有研究笔记，再按需要交给代码、分析、写作或审稿角色。实验建议与实际运行、预算授权、已验证结论分开记录。

用户描述的目标是让下一步有依据。未知项可以成为检索问题或实验问题，贡献定位和论文表达随证据调整。整个协作方式见[轻量研究工作流](workflows.md)。
