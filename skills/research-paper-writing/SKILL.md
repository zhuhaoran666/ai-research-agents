# 文献与证据驱动的科研写作

把值得研究的问题、有依据的方法增量和真实发现讲清楚。方法迁移、适配、整合与工具化都可以形成贡献，取决于解决的问题及支持证据。本技能服务写作与作者自查，提供论证方法，不规定段落数、文献配额或唯一论文结构；独立审稿交由专门审稿角色。

## 任务边界与材料

复用当前要求、已有授权、研究笔记、草稿、已核文献、方法说明和真实结果；材料够用就完成请求范围。只问会影响下一步且无法从现有材料判断的问题，同时推进不依赖答案的部分。不得把每次检索、阅读或编辑变成重复确认；改变研究问题、方法方向、关键实验协议或主张实质的取舍，应结合已有决定交由研究者判断，不能由写作需要代替科学决策。

按任务选择动作，不要求局部工作先完成整篇流程：

| 当前任务 | 采用哪些动作 | 交付范围 |
|---|---|---|
| 背景、相关工作或单个段落 | 必要的阅读比较、段落论证与语言检查 | 只写指定范围，不补作者方法、贡献或未提供的结果 |
| 引言、方法、实验章节或全文 | 组织主线、机制、证据及图表 | 完成所需章节；全文任务再检查跨章节一致性 |
| 翻译或局部润色 | 核对原意、术语与最小修改 | 不借润色改研究主线或补入科学内容 |

与已有技能按请求分工，不叠加整套流程：`paper-writer` 面向跨学科通用起草，本文侧重 AI 与技术研究的机制和证据组织；专门采用引言写作流程时可用 `intro-drafter`；纯语言润色优先用 `paper-polish`。这些是可用时的选择，不是运行本文的依赖。已有明确技能或领域要求时沿用，不另加固定篇章模板。

遵循用户指定语言和目标读者；未指定时结合现稿、交付用途与会话约定判断，确实影响写作且无法判断才询问。单独移植本技能只需保留本目录；项目约定与领域规范按当前任务提供，不自动读取私人档案。

## 1. 形成可论证的主线

需要组织主线时，先明确读者应带走什么认识：**要解决什么问题 → 最接近工作做到什么、还有什么具体困难 → 本文多做什么 → 哪项真实证据支持这一区别**。这是思考工具，局部写作只取相关项；清楚的中心问题可以支撑多项相关贡献。

区分已观察现象、原因假设、设计意图与实际验证。研究者的解释不能直接写成领域共识，分数提高也不能自动证明机制成立。按贡献选择重点：方法解释机制差异与替代解释；系统或工具交代能力、可靠条件与代价；数据或基准说明现有构建或评估无法回答什么；经验或理论说明改变了什么认识及其成立条件。

完整引言可用五个读者问题检查覆盖：**研究什么 → 为什么重要 → 难在哪里、直接做法为何不足 → 已有解法做到哪一步、本文补足什么 → 核心思路、实际结果及限制是什么**。难点应引出设计理由，价值落到具体能力、代价或认识变化；不要求写成五段。只写背景时只取相关问题。

研究尚未完成也可以起草问题陈述、已有方法说明、计划或已完成部分的正文。计划明确使用计划身份，不能把预期结果写成发现。缺少结果不妨碍交付有依据的部分，也不能仅因未提供材料就断言研究者未做；在稿件外简述缺口及其影响，不能将不完整草稿称为可投稿定稿。后续依真实结果更新主线，不要求实验维持早期故事。

## 2. 学习论文的论证动作并核对来源

先复用已有可靠阅读，再按当前论证缺口补查最相关原论文的引言、对应方法或实验上下文。论文解读与索引用于发现线索，不能代替原文；局部修词无需重做调研，也无需为达到引用数量扩大检索。

值得借鉴的动作可在现有笔记留一行：**来源、版本与位置 → 如何提出问题或组织证据 → 为什么适用本稿 → 本稿有哪些对应材料**。记录真实阅读范围，区分二手解释、原文事实与自己的推断。借鉴组织方式，不搬用独特措辞、图形或他人发现。

引用具体事实、数字、方法归因或比较前，核对所用来源的实际内容、版本及书目信息；来源存在不等于支持当前句子。摘要、搜索片段和书目条目只能支持其中实际可核的内容，不能据此补出方法细节或实验结论。无法核读时缩到已支持的表述，或交付其余正文并说明缺口；不编造引用、标识符、原文位置或阅读状态。引用格式沿用现稿或目标要求。

仅在需要学习实例或追溯这些规则来源时阅读：

- [论文案例学习记录](references/source-notes.md)：四篇论文的有限阅读记录、案例观察与本框架归纳，不是统一写作教程或当前课题的文献基础。
- [引言写作指南核读](references/introduction-guides.md)：区分原始建议与本框架适配，不将指南的固定长度或段数变成通用要求。

## 3. 从研究机制组织方法

先说明输入是什么，什么表示、信息、监督、优化过程或数据分布发生改变，预期为何有用；再按依赖关系展开模块、公式和必要实现细节。模块名称、类比或直觉不能代替机制解释或证明。

分别交代沿用组件、当前适配和实际验证的增量，与真实实现保持一致。组合方法解释组件为何需要一起工作；有交互时需要能区分交互与其他解释的证据，不机械要求所有贡献采用单因素消融。材料不清时指出具体缺口，不补造未提供的机制或实现。

## 4. 把材料写成段落

先确定本段要推进的判断，再选择依据、解释含义并承接上下文；不要求每段同一顺序。

- 背景与引言：从具体任务、现象或需求引出问题，承认已有进展，再说明当前范围内的不足；作者方案与贡献只在请求范围且材料支持时写入。
- 相关工作：围绕能力、条件与差异形成比较，让引用支持判断；不编造技术继承或用“现有方法均忽视”制造空白。
- 方法：先概览信息流与关键设计，再解释复现和理解所需的细节。
- 实验与讨论：围绕要回答的问题组织设置、观察与解释，区分实测发现和未验证假设，不逐行复述表格。
- 摘要、贡献与结论：与全文支持的价值一致，不突然引入更大的能力或额外机制结论。

## 5. 让证据与图表承担论证

整篇或关键章节可在现有笔记简要对应：**主张 → 真实结果、图表或原文 → 条件与可支持范围**。不强制新建台账。缺口先看已有材料或分析能否回答；确需新实验时说明它要区分什么解释和不补实验时的结论范围，交由研究者参与取舍。

定稿时从具体贡献反查方法、理论、实验或案例是否回答同一问题。正文结果变化后更新摘要、引言和结论；提到某模块不等于证实其作用，投入工时不决定正文篇幅。

公平比较保留数据、训练与测试条件、预算及评估口径。指标提高只支持相应测量；与主张有关的负结果、失败与代价如实解释。证据不足时收窄或明确标注主张的问题，不隐藏反例、替换评价标准或用更强措辞掩盖缺口。

每张图先确定要传达的判断：问题示例、机制关系或实验发现。概念示意与实测结果清楚区分，图注交代条件与读图所需信息；正文解释意义，不重复所有数值。真实数值来自可追溯的结果或分析，保留可编辑来源或重跑入口；写作任务不自动包含运行实验。

## 6. 保持语言自然与科学含义

中文先理解概念，再采用领域惯用表达；译词不清时说明对象、动作与现象。英文用准确搭配与清楚句法，不靠长句和高级词显得学术。保留必要术语，不把学术文本改成口语或将局部反馈扩成禁词表。

润色和翻译保持数字、比较对象、空间关系、因果强度、条件与不确定性。能局部修改就不重写整段。可能改变科学含义的改动在稿件外说明；未经授权的实质取舍保留原意并提出建议，不伪装成语言修正。突出真实价值，也保留影响结论的事实。

## 交付与检查

交付请求范围内的干净正文或明确状态的工作稿；没有来源的数字、占位引用和假装已完成的结果不进入成稿。来源核查、重大改动理由、实际完成范围与缺失材料简述在稿件外；用户要求批注稿时按其格式标注。

按本次范围核对：问题与比较有依据，机制与实现一致，主张与证据匹配，术语自然且科学含义保持。全文再检查摘要、引言、方法、图表、结果及结论的一致性；小段落不要求全稿审核。

在多 Agent 框架中，`writing` 起草和整合，`review-writing` 检查语言、指代与含义保持，`review-domain` 根据实际核读检查问题、比较和证据。需要独立审稿时交由这些专门角色；两位专家须以同一稿件版本、新上下文分别判断，首轮不以作者自评或另一专家的意见作为结论依据。本文自查与角色切换均不等于独立审稿；能力受限时如实说明。

有价值的反馈可在已授权范围内保存其来源、适用条件与验证状态，不强制每次写经验报告或修改技能。规则已保存、措辞被接受都不等于研究或写作质量已获验证。
