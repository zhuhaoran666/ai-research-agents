# 文献与证据驱动的科研写作

这是本研究框架自有的写作 Skill。目标是把值得研究的问题、有依据的方法增量和真实发现讲清楚；方法迁移、适配、整合与工具化都可以形成贡献。根据当前任务提出所需动作，不设固定段落数或文献配额。任何操作与发散 idea 先按[共享约定](../../agents/README.md)与用户讨论，操作经明确确认后执行；检索、阅读、起草、润色和经验记录同样适用。

## 输入与任务范围

复用用户要求、研究笔记、已有草稿、已核文献、方法说明和真实结果；有目标读者、投稿方向、语言与长度要求时一并参考。缺少某项材料时，说明影响任务的缺口，并讨论可交付的范围和具体操作；明确确认后执行，不自行扩大调查或改写范围。等待期间仅执行此前已讨论并明确确认的动作。

| 当前任务 | 采用哪些动作 | 交付范围 |
|---|---|---|
| 背景、相关工作或单个段落 | 阅读与比较、段落论证、语言检查 | 只写指定范围，不补作者方法、贡献或尚未提供的结果 |
| 引言、方法、实验章节或全文 | 按已有材料组织主线、机制、证据和图表 | 先完成所需章节，全文任务再核对跨章节一致性 |
| 翻译或局部润色 | 核对原意、术语与最小修改 | 不强行重构研究主线；新增事实或比较时补查 |
| 审稿 | 按角色独立检查相应部分 | 给出有定位的意见，不将作者自查当审稿结论 |

## 1. 形成可论证的研究主线

需要组织主线时，先明确希望读者带走什么认识，再可在工作笔记中用几句话回答：**读者要解决什么问题 → 最接近工作已做到什么、还有什么具体困难 → 本文多做了什么 → 哪项真实证据支持这一区别**。清楚的中心问题可以支撑多项相关贡献。这帮助思考，不是正文句式模板；局部写作只用相关项。

先区分已观察的现象、原因假设、方法意图与实际验证。研究者提出的原因不能直接写成领域共识；分数提高也不能自动证明原因成立。尚未完成实验时写问题与待验证思路，不能虚构研究发现。

完整引言可用五个读者问题检查是否讲清：**具体研究什么 → 对目标读者为什么重要 → 难在哪里、直接做法为何不够 → 已有解法做到哪一步、本文补足哪一部分 → 核心思路与实际结果是什么**。这些是覆盖检查，不要求写成五段；问题价值要落到具体能力、代价或认识变化，难点要自然引出方法选择，避免只写“重要且具有挑战性”。只写背景时取前面有关问题即可。

研究早期也可以写摘要和引言草稿，用它们暴露问题、机制或验证思路不清之处，再与研究者完善方案。未确认的贡献与预期结果留在工作笔记中；后续依据真实结果修订，不为维持早期故事要求实验给出预定答案。

按实际贡献选择论证重点，而非强制归类：

- 方法：具体机制与原有解法的差别，什么证据能区分替代解释。
- 通用工具或系统：带来什么可用能力，在哪些任务和条件下可靠，代价是什么。
- 数据或基准：现有资源或评估回答不了什么问题，新的构建与评估如何补足。
- 经验发现或理论：观察或结论改变了什么认识，在什么条件和证据下成立。

## 2. 学习论文的论证动作

用 PaperNotes、论文解读或索引发现线索，再读最相关原论文的完整引言、对应方法和实验段落。按问题、贡献类型和读者选择范文；本 Skill 不用几篇示例代替当前课题的文献基础。已有核读记录可以复用，局部修词无需重做调研。

每个值得借鉴的动作可留一行：**来源与版本/位置 → 怎样提出问题或组织证据 → 为何适用本稿 → 本稿有哪些对应材料**。记录真实阅读范围；二手解读的概括、评分、历史判断和推测，不能冒充原论文结论。

参考[论文案例学习记录](references/source-notes.md)理解这种读法；其中是案例观察与本框架归纳，不是作者发布的统一写作教程。[引言写作指南核读](references/introduction-guides.md)另区分写作指南的原始建议与我们的适配。借鉴组织方式，不搬用独特措辞、图形或他人的发现，也不强行模仿章节数。

## 3. 从研究机制组织方法

先用清楚的语言说明：输入是什么，什么表示、信息、监督、优化过程或数据分布发生了改变，预期为什么有用。然后按依赖关系展开模块、公式和实现细节；模块名称不能代替机制解释。

分别交代沿用的组件、当前适配及真正验证的增量。组合方法说明组件为什么需要一起工作；有交互时选择能检验交互的证据，不机械要求所有贡献只做单因素消融。类比或直觉用来解释设计，不当作机制证明。

## 4. 把材料写成段落

先确定本段要让读者理解的一个判断，再选择必要依据并解释其含义，按逻辑承接上下文。不要求每段照同一顺序展开；读者应能复述本段推进了什么。

- 背景与引言：从具体任务、现象或需求引出问题；承认已有进展，再说明与当前范围有关的不足。作者方案与贡献只在请求范围内、材料支持时写入。
- 相关工作：围绕能力、条件和差异比较方法，让引用支持判断。没有原文依据时不编造技术继承或单向演进，不用“现有方法均忽视”制造研究空白。
- 方法：先概览信息流与关键设计，再解释必要细节；与真实实现保持一致。
- 实验与讨论：先说要回答的问题，再解释设置、观察及其支持的判断。区分实测发现、解释与未验证假设，不能只逐行复述表格。
- 摘要、贡献和结论：围绕同一项成立的价值组织，主张范围随全文证据更新，不突然引入更大的能力或额外机制结论。

## 5. 让证据与图表承担论证

整篇或关键章节可在现有笔记中简要对应：**主张 → 真实结果/图表/原文 → 条件与可支持范围**。不要求额外填表；缺口先考虑补写或重整已有分析，确需新实验时提出能区分解释的最小方案，由研究者参与取舍。

定稿时从引言中的具体贡献反查正文：哪段方法、理论、实验或案例支持它，证据是否回答了同一个问题。正文结果变化后反向更新摘要、引言和结论；不能把“正文提到该模块”等同于证实其作用，也不能按研究者投入的工时分配篇幅。

公平比较保留数据、训练与测试条件、预算和评估口径。指标提高只支持对应测量，不能写成所有场景均有效、临床可用或拓扑必然正确。与主张有关的负结果和代价如实解释；证据不足时收窄主张，不隐藏反例或事后悄悄改评价标准。

每张图先确定要传达的判断：问题示例、机制关系或实验发现。概念示意与实测结果清楚区分，图注交代条件及读图所需信息；正文解释意义，不重复所有数值。真实数据和分析由相应研究角色提供，保留可编辑来源或重跑入口。

## 6. 使用自然、准确的学术语言

中文先理解概念，再采用领域惯用表达；译词不清楚时直接说明对象、动作与现象。保留准确术语，不把全文改成口语，也不把局部反馈变成禁词表。英文使用准确搭配和清楚句法，不为显得学术堆砌长句或高级词汇。

润色不得改变数字、比较对象、空间关系、因果强度、条件和不确定性。能用局部修改解决的问题就不重写整段。突出真实价值、避免空泛自贬，同时准确呈现会影响结论的事实。

## 交付与独立检查

交付用户请求范围内的干净正文或审稿意见。阅读范围、来源核查、重大改动理由与缺失材料放在稿件外；没有来源的数字、占位引用和计划中的结果不进入成稿。

交付前按本次范围核对：问题与比较有依据，机制与实现一致，主张与证据匹配，术语及语言自然，修改保持科学含义。全文再对照摘要、引言、方法、图表、结果与结论；小段落不强制全稿审核。

在多 Agent 框架中，`writing` 负责起草和整合；`review-writing` 独立检查语言、指代与含义保持；`review-domain` 实际核读文献并检查问题、比较及证据。两位专家先独立判断同一稿件版本，不能用本 Skill 自查代替审稿；角色切换不等于上下文独立。

根据用户反馈修订当前文本，再记录值得复用的经验与适用范围。新增规则先用实际段落、原文或结果检查；未得到支持的策略保持候选，不将保存 Skill 或用户接受措辞等同于研究质量提高。
