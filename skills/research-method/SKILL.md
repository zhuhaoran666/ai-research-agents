# 从问题到可检验方法

设计能改变研究判断的验证，而非默认扩成大型实验矩阵。将方案、设计理由、可检验假设和已验证结果分开，保留可能失败的解释。

## 最小输入与当前状态

从当前问题或待检验主张开始，复用已有方案、文献比较、数据条件、运行与资源约束。只追问会改变下一步的缺口；尚不清楚的预算、数据可用性或机制保持未知，不编造条件以凑齐计划。

先理解同任务已有解法及局限，再判断候选工具是否必要；工具能优化某目标，不等于目标任务需要它或会优于已有方法。缺少最接近工作时提出针对性补查，已有可靠依据可直接沿用，不要求每次完整调研。

## 明确机制与可反驳假设

把主张整理成简短链条：**具体问题或观察 → 原因假设与替代解释 → 拟改变的机制 → 可观察差异 → 什么结果会削弱假设**。观察、解释、直觉和证据分别标明，不能把性能提升预先写成机制证明。

与最接近方案比较：沿用什么、适配什么、实际新增什么，以及哪项同条件比较会使增量不成立。迁移或组合可以有价值，但应解释条件和必要性；跨任务时核对假设、分布、输出语义与交互条件，表面现象相似不等于共享机制。

提出少量有实质区别的候选，比较可检验性、预期信息量、实现难度、资源和失败条件。优先让已有数据或分析回答关键问题；确需新增验证时，从最能区分解释的小实验开始，不能只列“增加实验、更多数据”。

## 选择能回答问题的对照

对每项主要主张找到相应支持方式：受控比较、必要消融、交互设计、理论推导、诊断或案例核查按贡献性质选择。单因素对照适合隔离独立因素；强交互或耦合机制可能需要联合设计，不能机械要求每项贡献只能对应一个单因素消融。

简单而合理的基线与最接近强基线都应考虑；核对标准设置、调参和实现可达性。没有采用更强版本时给出与当前问题有关的理由，而非只挑容易超过的对手。参照工作中有效不等于当前实现已复现。

多任务、数据集、种子和消融数量由主张、变化来源与资源决定，不设默认大矩阵。先判断什么证据会改变决定，再安排扩展；有效负结果不自动触发无边界搜索。

## 将关键验证写成可执行协议

按本次主张保留必要字段，简单验证可用短条目，不强制新建表格：

| 要素 | 进入正式验证前需要明确的内容 |
|---|---|
| 问题与比较 | 检验哪条假设、比较什么、控制哪些变量，结果能排除和不能排除什么解释 |
| 独立评价单元 | 样本之间的分组、时间或重复结构；数据划分与预处理、特征选择、调参如何避免泄漏 |
| 选择与最终测试 | 选型用什么资料、何时冻结配置；最终测试不反复用于选型，无法分离时标为探索性 |
| 公平性 | 数据、训练与搜索预算、后处理、选择规则是否可比；差异及其对结论的限制 |
| 指标与不确定性 | 指标方向、聚合与单位，适用的效应量、波动来源及估计或重复方式；不把单次最好值当稳定优势 |
| 成本与可行性 | 数据和标签是否够用，实现依赖与测量能否支持问题，训练、搜索、推理及人工成本的口径 |
| 决定与停止 | 何种结果支持、削弱或仍无法判断假设，何时停止、复查实现或转向；资源上限及失败处理 |

定量阈值应有实际依据；没有可靠波动估计时先用诊断性验证估计，不凭空填写成功标准。非定量或理论贡献采用对应的论证与反例标准，不能强套训练测试指标。

研究者参与研究问题、方法方向及关键评价协议的选择；复用已有决定与授权，范围内的细化直接推进。需要改变冻结协议、数据用途、主要比较或资源额度时，明确依据与影响再对齐，不能通过写作或实现便利悄悄替换协议。

## 依据结果修订

交代码角色的计划要能实施，标明数据与配置来源、当前版本、先后依赖及完成依据；工程可行性由实际检查补足，不把方案图当运行成功。分析角色核对结果可比性和不确定性，再判断下一步。

新建议关联原始运行、证据缺口及变更理由，区分实现修复、负结果诊断和新假设。协议变化保留旧版本、原指标与结果；不事后改变成功标准、筛选有利设置或将不利对照移出报告。

证据不足时同时给出最小补证与不补实验可保留的主张范围。结果推翻设计直觉时修改或放弃假设，不为维护初始方法强行解释。具体统计、领域实验、伦理和数据要求复用相应专长，不把单一领域规则扩为通用协议。

## 交付

交付方法草图、关键依据和可执行的最小验证计划，说明方案间的取舍、尚未确定的条件、资源与停止判断。已有材料够用时直接形成计划，不要求先走完整研究流程。

标明哪些是用户提供、文献支持、可行性推断或待验证假设；未经实际运行不能称已实现，未经相应证据不能称有效或证明机制。计划完成以执行者能开展验证、研究者能理解取舍为准，格式校验或方案获认可都不等于科学结论成立。
