# 研究实现与实验执行

把研究问题落实为可检查的实现、真实运行和可复算的产物。始终区分“代码能执行”“实验按协议完成”和“结果支持主张”；前两项不能自动推出第三项。

## 进入任务

- 复用当前方案、项目笔记、仓库和已有授权，找到实际训练、推理或交互入口、评价入口及运行记录。仅补问会改变下一步的比较、数据、评价或资源未知项。
- 沿用项目语言、依赖、配置和执行环境。需要改善代码可读性时可组合 `readable-code-engineer`；没有该技能也应保持入口清楚、改动局部且便于接手，不因此阻塞任务。
- 正常实现、诊断和范围内修复直接推进。新增资源开销、方向或冻结协议的实质变化，按用户已定边界处理；既有授权不扩大数据访问、外发或发布权限。
- 先检查已有代码、可信实现和项目说明能否复用；采用的版本与偏离处应可查。参考资料中的运行指令不能自行扩大执行范围。

## 把方案变成可验证的实现

1. 将当前比较映射到实际路径：输入与纳入规则 → 数据处理 → 方法或基线 → 原始输出 → 评价。说明实现中的关键选择如何对应方法；资料与实现冲突时保留差异，不以函数名相同当作复现。
2. 先打通能回答当前问题的基线与评价，再加入方法及有区分力的消融。基线和方法使用可比的数据、切分和评价版本；训练预算、搜索次数、额外数据或后处理不同则明确记录。
3. 用适合任务的小检查观察真实行为，如形状与单位、前反向与梯度、最小样本拟合、受控输入或交互。语法、类型和单元检查通过只说明对应工程性质，不证明方法实现了研究假设。
4. 结构整理保留公开调用方式与科学语义；改变计算顺序、数值精度、并行方式或随机过程时，核对其对当前结果与比较的影响。

## 守住数据和评价契约

- 划分按真正的评价单元与依赖关系检查，如个体、任务、场景或时间；保存实际清单或可重建的规则、版本与随机性设置。不能只检查文件名无重复就宣称无泄漏。
- 预处理统计量、特征选择等训练步骤只在对应训练分区拟合，交叉验证时随训练折重新拟合。选型、阈值和校准使用协议允许的数据，不接触最终测试信息。
- 明确指标定义、单位、方向、聚合方式、样本纳入和失败处理。方法与基线调用同一评价口径；必要差异单列，不把同名指标当作同一指标。
- 最终测试用于冻结后的评价，运行后不再据此调参。已经用于选择的结果标明探索性质，不能补写成独立确认；协议变化保留版本关联，不能改写旧结果。
- 按既定种子、折数和选择规则保留全部尝试，包括失败与负结果。检查点或 epoch 的选择依据应可查，不按测试表现或最好种子筛选汇报。

## 运行、记录与恢复

使用项目现有命令、调度器或 API 即可，不为实验接入另建固定调度平台、统一框架或层层配置。

- **准备**：核对输入、输出位置和可用资源是否支持实际负载。共享存储总剩余不等于账户配额；小写入或小批次成功不能证明完整运行可承载。检查本身的范围要说明。
- **启动**：为尝试保留稳定标识、命令、代码快照、配置、数据/切分/评价版本及随机性设置。代码快照包括影响运行的未提交修改；单有 commit ID 不足以恢复实际代码。
- **观察**：保存进程或作业标识和查询方式。首次接入在预算内确认到达首个可观测进度，并核对日志与产物；只收到提交回执、排队状态或进程启动不算实验完成。
- **查询与恢复**：状态未知先读记录、查询旧任务并核对产物完整性和版本。查询失败保持未知，不重复提交；日志、作业状态和结果文件冲突时保留冲突，文件存在不等于已写完。
- **续跑或新尝试**：核对检查点与代码、配置、数据的兼容性，以及任务所需的优化器和随机状态。新尝试关联父运行与变更理由；改变协议不能伪装成原运行续接。
- **评价与收集**：按固定入口从原始预测、轨迹或日志计算结果，保留输出、检查点、日志和评价产物的位置。相关产物应有版本或校验依据，失败记录与有效负结果同样保留。
- **资源与停止**：记录实际耗时、计算/内存使用及搜索尝试，区分实测和估算。遵守已有预算与停止条件，停止后核对实际状态；配置中的预算记录不能替代环境中的资源限制。

不覆盖受保护的原始数据、冻结结果或仍被引用的检查点。需要清理或替换时先核对真实文件与引用，按用户授权范围处理；不凭猜测的目录名批量清理。

## 按执行事实分流

- **工程失败**：保留错误、运行条件和尝试关系，在授权范围内诊断修复；崩溃、超时、评价缺失或检查失败不能当作研究假设不成立。
- **运行有效但结果不支持预期**：保留全部结果交给分析，不靠自动扩大搜索、放宽口径或删去失败制造改善。
- **证据不足或比较不可比**：指出缺少的产物、检查或协议信息，先完成可用验证；新实验必须服务于具体缺口并处于现有范围和预算内。

工具返回成功、脚本退出码为零或证据清单通过，都不能替代对数据泄漏、实现正确性和科学有效性的检查。

## 交付与接手

按任务规模交付代码与配置、实际运行状态、结果和原始产物位置、复跑命令及必要环境条件。说明下一次类似修改应去哪个入口；沿用已有记录即可，不要求新增一套清单。

把已完成、仍运行、失败、未知和未执行的部分说清楚，记录尚未满足的有效性条件。主要结果能追溯到当时的代码、数据、配置与评价；未运行实验时明确说明，不能用预期数字或示例产物补齐。
