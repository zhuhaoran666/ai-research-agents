# 示例：固定计算预算下的高效适配

**这是虚构的研究起点，用于演示分工。文献、数据和预算尚未确定，没有运行实验或取得结果，也不声称提出了新方法。**

## 问题与初始想法

假设研究者需要把一个预训练模型适配到多个新任务，但每个任务的训练预算有限。初始直觉是：不同模块对当前任务的重要性可能不同，能否利用一次短暂探测，选择值得更新的模块，把计算用在更有价值的位置？

“模块重要性可被低成本估计”与“选择策略能迁移到未参与开发的任务”都是待验证假设。文献调研可能发现已有等价方案；此时应调整问题或研究其适用边界。

研究者与方法角色先确定：希望优化哪种成本、是否允许离线预处理、可用硬件与总预算，以及是否主张跨任务迁移。下表只展示交接内容。

## 七个角色怎样接手

| 角色 | 当前任务 | 给下一位的材料 |
|---|---|---|
| `mentor` | 与研究者明确实际需求和预算，检查“成本更低”是否值得研究；按阻塞和优先级调度 | 研究笔记中的目标、已确定条件、待确认的重要取舍 |
| `literature` | 检索选择性更新、参数高效适配和预算分配等相关工作；阅读最接近方法和官方实现，找强基线及反例 | 有真实来源和阅读范围的方法比较；已有方案与初始想法的重合、差异和未知 |
| `method` | 与研究者据文献修改方案，定义选择信号与实现边界；和代码、分析角色设计能区分解释的最小实验 | 方法草图、可执行的比较表、预期成本与可能推翻假设的观察 |
| `code` | 实现共同训练与评价入口，接入基线和候选方法；计入探测、选择与训练成本，在约定预算内运行 | 版本、配置、实际命令、日志、指标文件及失败记录；运行成功与科学结论分开记录 |
| `analysis` | 比较质量、实际成本与波动，检查收益是否来自额外搜索、不同可训练参数量或不公平的调参 | 从原始输出生成的表图数据、失败案例、竞争解释和下一步建议；交给方法角色讨论优化 |
| `writing` | 核读支撑主线的论文，同时学习相近贡献如何写；以真实结果组织问题、比较和图表 | 段落草稿、图表及其数据来源；把证据缺口交给文献、方法或分析角色 |
| `reviewer` | 独立补查最接近工作，检查贡献定位、成本核算、比较公平性和跨任务结论 | 有来源和稿件定位的主要意见，说明每个问题影响哪项结论，并建议最小必要修订 |

导师汇总分歧和优先级，研究者参与核心假设、实验设计和结论取舍。方法与分析可直接协作，普通代码修复直接推进；写作中的新发现也可以触发补查或小实验。

## 第一组实验要回答什么

先在一个开发任务上验证可行性，再按主张和资源选择有实质差异的任务。基线要经过文献核实，以下是比较类别，不是已选定的算法。

| 疑问 | 候选比较 | 需要记录的证据 |
|---|---|---|
| 分配策略是否有价值？ | 候选选择策略与简单固定策略、匹配更新量的随机策略，在相同预算内比较 | 任务质量、端到端时间、峰值显存、更新参数量与运行波动 |
| 收益是否抵得上选择成本？ | 包含全部探测开销的候选策略与最接近的高效适配基线 | 总成本明细和不同预算下的质量，不只报告正式训练阶段 |
| 策略能否复用？ | 冻结在开发任务上确定的策略，再应用于未用于择优的任务 | 开发接触范围、逐任务结果和失败案例；重复次数按噪声与预算决定 |

评价集用于方法开发，最终测试用于报告；需要额外超参数搜索时记录并纳入比较。若选择开销超过收益，下一步可能是简化选择、限制适用场景，或结束该方向，而非只寻找更好看的任务。

## 最小复现材料

沿用现有项目结构即可：一份研究笔记保存问题、文献和关键取舍；代码与配置能还原每次主要比较；运行日志保留原始输出；论文图表能追溯到结果文件与生成入口。没有真实运行前，结果表保持空白，写作仅覆盖已有依据的背景、相关工作和待验证设想。
